# reco-bench

Бенчмарк рекомендательных систем на **неявной обратной связи** (implicit feedback):
сравнение базовых моделей, собственной реализации ALS и BPR-MF по ранжирующим метрикам.

Проект вырос из личной разработки (пилота по рекомендательным системам) и
существует в открытом виде: код, тесты, CI и воспроизводимые результаты.

> Данные, на которых велась исходная разработка, распространяются под правилами
> соревнования и **не входят в репозиторий**. Вместо них здесь лежит генератор
> синтетического датасета той же схемы — весь пайплайн, тесты и CI работают
> на нём, а инструкция по подключению реальных данных — в [docs/DATA.md](docs/DATA.md).

---

## Что внутри

| Компонент | Описание |
|---|---|
| **ALS** | Собственная реализация неявного ALS (confidence-weighted MF) на PyTorch. ALS-шаг решается **сопряжённым градиентом (CG)** — факторы плотные, разреженная только матрица взаимодействий. |
| **BPR-MF** | Матричная факторизация с попарной ранговой функцией потерь BPR и сэмплированием негативов. |
| **Popularity** | Базовая линия: глобально популярные айтемы. |
| **ItemKNN** | Item-based collaborative filtering по косинусной близости с отсечением по числу соседей. |
| **PureSVD** | Базовая линия: усечённое SVD матрицы взаимодействий. |
| **Метрики** | MAP@k, Recall@k, NDCG@k, покрытие каталога, новизна. |
| **Схемы весов** | `rich` / `binary` / `like` — как из сырых действий пользователя получается «вес интереса». |
| **Сплит** | Временный holdout: последние N взаимодействий каждого пользователя уходят в тест. |

Всё считается на CPU, детерминированно по seed, без внешних сервисов.

## Быстрый старт

```bash
git clone https://github.com/Xyecoc2019/reco-bench.git
cd reco-bench

python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate

pip install -r requirements.txt

# 1) сгенерировать синтетический датасет (тот же формат, что и у реальных данных)
python scripts/generate_synthetic_data.py --out data/synthetic_train.parquet

# 2) прогнать бенчмарк
python -m reco_bench.experiment --data data/synthetic_train.parquet --schemes rich --k 16 --out results

# 3) тесты
pytest -q
```

Результаты появятся в `results/results_<scheme>_k<k>.csv` и `.json`.

Подбор гиперпараметров ALS и сборка отчёта:

```bash
python scripts/hyperparameter_sweep.py --data data/synthetic_train.parquet \
    --schemes rich,binary --ks 8,16,24,32 --alphas 1,10,40 --regs 0.01,0.05 \
    --out results/als_hyperparameter_sweep.json
python scripts/make_report.py --results results --out docs/RESULTS.md
```

### Основные ключи запуска

```
--data PATH       parquet с взаимодействиями (по умолчанию $RECO_DATA_DIR/train.parquet)
--schemes LIST    rich,binary,like — какие схемы весов прогонять
--k N             число латентных факторов (по умолчанию 16)
--als-iters N     итераций ALS
--cg-iters N      итераций сопряжённого градиента на одном ALS-шаге
--alpha A         усиление уверенности для наблюдаемых пар
--reg R           L2-регуляризация
--bpr-epochs N    эпох BPR
--holdout N       размер holdout на пользователя
--topk N          сколько рекомендаций выдаём
--out DIR         куда складывать таблицы результатов
--skip LIST       какие модели пропустить (popularity,itemknn,puresvd,als,bpr)
```

### Схемы весов

Сырой лог — это набор флагов (`like`, `dislike`, `share`, `bookmark`,
`click_on_author`, `open_comments`) и время взаимодействия. Из него нужно
получить одно число «веса интереса»:

| Схема | Положительный пример | Вес |
|---|---|---|
| `like` | только явный лайк | 0 / 1 |
| `binary` | любое действие или время выше медианы | 0 / 1 |
| `rich` | то же множество, что в `binary` | взвешенная сумма действий + 0.5·log(1 + время) |

`dislike` в любой схеме обнуляет вес и убирает взаимодействие из positives.

### Оценка

Холдаут — **последние 10 взаимодействий каждого пользователя** (в порядке файла).
Метрики считаются по top-10/20/50 рекомендаций; уже показанные в обучении
айтемы из выдачи вырезаются, поэтому «попадание» означает новое интересное
событие, а не повтор.

## Результаты

Синтетический датасет: 4 000 пользователей, 1 500 айтемов, ~240 тыс. взаимодействий,
12 латентных тем. Команда воспроизведения:

```bash
python scripts/generate_synthetic_data.py --out data/synthetic_train.parquet
python -m reco_bench.experiment --data data/synthetic_train.parquet \
    --schemes rich,binary,like --k 16 --out results
python scripts/make_report.py --results results --out docs/RESULTS.md
```

<!--RESULTS_TABLE-->

Схема `rich`, `k = 16`:

| Модель | MAP@10 | Recall@10 | NDCG@10 | Coverage@10 | Время, с |
|---|---|---|---|---|---|
| **ALS** (своя реализация, CG) | **0.0392** | **0.0933** | **0.0703** | 0.702 | 0.4 |
| ItemKNN | 0.0297 | 0.0731 | 0.0563 | 0.579 | 0.7 |
| PureSVD | 0.0224 | 0.0560 | 0.0420 | 0.164 | 0.4 |
| BPR-MF | 0.0106 | 0.0303 | 0.0217 | 0.319 | 0.5 |
| Popularity | 0.0037 | 0.0120 | 0.0080 | 0.011 | 0.4 |

Что видно из абляций (полные таблицы — в [docs/RESULTS.md](docs/RESULTS.md)):

* **ALS выигрывает у всех бейзлайнов** при `k = 16` (MAP@10 0.039 против 0.030 у ItemKNN),
  но проигрывает при `k = 32` и `k = 64` — на таком объёме данных модель переобучается;
* **`alpha` зависит от схемы весов**: при `rich` (веса 1–10) лучше `alpha = 1`
  (0.0406), при `binary` (веса 0/1) — `alpha = 40` (0.0431, лучший результат во всём прогоне);
* **`reg` почти не влияет** на качество (0.0392 против 0.0398 при `reg = 0.5`), зато сильно
  влияет на покрытие каталога;
* **`Popularity` даёт минимальное покрытие** (0.011) — все пользователи получают одну и ту же
  выдачу, это его главное ограничение;
* **BPR-MF заметно слабее** при 6 эпохах и одном негативе на пару — увеличение числа
  негативов и эпох это направление для дальнейшей работы.

Полные таблицы (включая абляции по `k`, `alpha` и `reg`) — в [results/](results/),
описание экспериментов — в [docs/EXPERIMENTS.md](docs/EXPERIMENTS.md).

## Тесты и CI

```bash
pytest -q
```

Тесты покрывают схемы весов (в том числе что `dislike` всегда обнуляет вес),
корректность temporal holdout, агрегацию повторных взаимодействий в матрице,
метрики на эталонных примерах, детерминированность ALS, снижение ошибки
восстановления и полный прогон пайплайна.

GitHub Actions (`.github/workflows/ci.yml`) на каждом коммите: установка
зависимостей → генерация данных → `pytest` → smoke-прогон бенчмарка.

## Воспроизводимость

* фиксированный `seed` (по умолчанию 0) — ALS и BPR детерминированы;
* результаты пишутся и в CSV, и в JSON (с полными аргументами запуска);
* зависимости зафиксированы минимальными версиями в `requirements.txt`;
* тесты идут на Python 3.10 и 3.12.

## Ограничения и что дальше

* ALS реализован на PyTorch без GPU-оптимизаций — на больших данных имеет смысл
  переносить half-step на CUDA;
* обучение идёт по сырым логам без предобработки (дедупликация, фильтрация ботов);
* нет онлайн-метрик (CTR, retention) — только офлайн-качество ранжирования;
* следующие шаги: implicit-feedback обработка с временными весами (time decay),
  гибрид Popularity + ALS, перебор гиперпараметров, экспорт рекомендаций в
  формат для продуктового стенда.
