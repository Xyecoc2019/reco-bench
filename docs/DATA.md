# Данные

## Что нужно

Один parquet-файл с логом взаимодействий: **одна строка = одно взаимодействие
пользователя с контентом**.

| Колонка | Тип | Смысл |
|---|---|---|
| `user_id` | int / str | идентификатор пользователя |
| `item_id` | int / str | идентификатор контента |
| `place` | str | где был показан контент (лента, поиск, ...) |
| `platform` | str | клиент (android / ios / web) |
| `agent` | str | версия клиента |
| `timespent` | float | время взаимодействия, секунды |
| `like` | bool | лайк |
| `dislike` | bool | дизлайк |
| `share` | bool | репост |
| `bookmark` | bool | в закладки |
| `click_on_author` | bool | переход к автору |
| `open_comments` | bool | открыл комментарии |

Обязательны для пайплайна: `user_id`, `item_id`, `timespent` и все булевы колонки
сигналов (`like`, `dislike`, `share`, `bookmark`, `click_on_author`,
`open_comments`). Остальные можно оставить как есть или заполнить константой.

## Как подключить реальные данные

Исходный датасет, на котором велась разработка, — лог кликстрима из соревнования
по рекомендательным системам. Он распространяется под правилами соревнования,
поэтому в репозитории его нет. Чтобы прогнать бенчмарк на нём:

1. скачайте файл со страницы соревнования (файл должен быть в формате parquet
   с схемой из таблицы выше);
2. положите его в `data/` под именем `train.parquet` — либо укажите путь
   явно через `--data path/to/file.parquet`, либо через переменную окружения
   `RECO_DATA_DIR` (тогда файл должен лежать в `$RECO_DATA_DIR/train.parquet`);
3. запустите:

```bash
python -m reco_bench.experiment --data data/train.parquet --schemes rich --k 32 --out results
```

Файл читается через `pyarrow.parquet.read_table`, а не `pandas.read_parquet`:
в части снимков датасета футер parquet повреждён, и pandas отказывается его
читать, хотя сама таблица целая.

## Синтетический датасет

Если реальных данных нет, сгенерируйте аналог:

```bash
python scripts/generate_synthetic_data.py --out data/synthetic_train.parquet \
    --users 4000 --items 1500 --topics 12 --interactions 60 --seed 0
```

Генератор строит лог с теми же колонками и с той же структурой:

* латентные темы — у пользователей и у контентов (разреженные векторы);
* вероятность показа айтема пользователю пропорциональна близости его темы
  к теме айтема и «популярности» айтема (длинный хвост);
* `like` / `dislike` / `share` / `bookmark` зависят от близости и добавляют шум;
* `timespent` — логнормальное распределение, сдвинутое близостью айтема.

Параметры по умолчанию дают ~240 тыс. взаимодействий, 4 000 пользователей и
1 500 айтемов; генерация детерминирована по seed.
